# 見た目の決まりごと

Compile の画面を作る・直すときは、ここに合わせる。新しい画面や演出を足す前に読むこと。
(色や書体の実物は `three-play.html` の `:root`、盤面側は `js3d/theme.js`)

## 全体の方向

- 夜の電子盤。黒に近い紺の地に、桃・紫の光。明るい画面・白地は使わない。
- 画面の文は日本語。英字は、ロゴ・勝敗・見出しの飾り (VICTORY、YOUR TURN、REMATCH など) だけにする。
  説明や案内は必ず日本語で書く。
- 角は丸めず、斜めに切り欠く (左上と右下)。丸いピル形のボタンは作らない。

## 色

| 名前 | 値 | 使いどころ |
|---|---|---|
| 地 | `#03040a` | 画面の一番奥 |
| 板 | `rgba(12,9,20,.9)` | 画面の上に出す板・一覧 |
| 文字 | `#f1edf8` | ふつうの文字 |
| 薄い文字 | `rgba(241,237,248,.55)` | 補足・ラベル |
| 桃 | `#ff4fa3` | 相手・負け・強調の1点 |
| 紫 | `#8b5cf6` / `#a07bff` | 自分・勝ち |
| 薄紫 | `#b9a4ff` | 枠線・区切り |
| 淡い桃 | `#ffb3da` | 金の代わり (レベル・ごほうび・大事な数字) |

- 自分は紫、相手は桃。手番の帯・勝敗・盤面の光でこの割り振りを崩さない。
- プロトコルの色 (FIRE の赤など) はカードとプロトコル板の中だけで使い、画面の枠には使わない。

## 書体

- ロゴ・勝敗など大きな英字: Orbitron (`--font-logo`)
- 見出し・ボタン・数字: Oxanium (`--font-hud` / `--font-ui`)
- 日本語: system-ui (ヒラギノ・Noto Sans JP)。Orbitron と Oxanium は日本語を持たない
- 数字が並ぶところは `font-variant-numeric: tabular-nums`

## 絵 (スリーブ・プレイマット・カードの絵)

- つやのある「AI っぽい」絵にしない。光沢・ハイライト・ぼかしたきらめきは入れない。
- 好みは花札・北斎のような版画調・平塗り。輪郭がはっきりした、少ない色の絵。
- 絵は手元の Stable Diffusion (E:\SD の SwarmUI) で作る。お金のかかる生成は使わない。
- 素材サイトの絵を使うときは、使ってよい条件 (商用・表記) を必ず確かめる。3D のつやのあるアイコン集は合わない。
- カード裏の FACE DOWN の帯の下に、絵の大事なところが隠れないようにする。

## 動き

- 待ち時間を足さない。演出は、もともとある待ちの中に収める。何度も通る流れほど短く。
- 動きを減らす設定 (`prefers-reduced-motion`) では、回る・揺れる・数え上げる動きを止めて最後の形を出す。
- 使える部品 (素の CSS / JS。React の部品集は見本にして作り直す):
  - `js3d/feel.js` — 合計値の増減が浮かぶ、READY、CPU が考え中の輪、振動
  - `js3d/motion.js` — 数字の数え上げ (`countUp`)、1つずつ配るように出す (`dealIn`)
  - `js3d/holo.js` — カードを傾けて光らせる (ガチャで出たカードなど、1枚を大きく見せるとき)
  - 回る光の枠 — 1つの画面で一番押してほしいボタン1つだけ
- ゲームの操作そのもの (カードを置く・選ぶ) の判定には手を入れない。

## 文の書き方

- 何が起きるかをそのまま書く。「REFRESH」より「手札を5枚まで引く」。
- エラーは、何が起きたかとどうすればいいかを書く。謝らない。
- 読む人の側の言葉で書く (「同期の失敗」ではなく「別の端末の記録と合わなかった」)。

## 画面の大きさ

- スマホの縦持ち (幅 390px 前後) と、PC の横長の両方で確かめる。横にはみ出して横スクロールが出たら直す。
- 上端・下端はスマホの時計やホームバーの分 (`env(safe-area-inset-*)`) をあける。
